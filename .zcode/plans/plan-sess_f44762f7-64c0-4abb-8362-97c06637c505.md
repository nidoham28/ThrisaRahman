# Add tool-call support to the chat UI

## Context

Tool calling already works end-to-end in this app: 60 tools are registered in `ToolRegistry` → passed via `AssistantApiService.streamChat()` → the `:ai` module's `runAgent()` loop does native function calling (Gemini Interactions API / OpenRouter OpenAI) → `BuiltinToolExecutor` executes → results feed back into the model. 

**The gap:** none of it is visible. The chat UI (`ChatPage`) renders a flat `UiMessage(text, imageUri)`; tool activity appears only as a transient "Running tool: X…" status line. This plan adds visible tool-call cards inside assistant bubbles — compact chip per tool call (friendly name + status), tappable to expand arguments and result — matching the existing dark theme.

Per `ASSISTANT.md`, only `:app` may be edited — this plan touches only `:app`.

## Changes

### 1. `app/src/main/java/com/naira/assistant/presentation/main/AssistantViewModel.kt`

- Add next to `UiMessage` (line ~43):
  ```kotlin
  data class UiToolCall(
      val id: String,        // toolCallId (stable Compose key)
      val name: String,      // wire name, e.g. "set_timer"
      val input: String,     // raw JSON argument string
      val isRunning: Boolean,
      val isError: Boolean,
      val result: String,    // tool output text (pretty-printed)
  )
  ```
- Extend `UiMessage` with `val toolCalls: List<UiToolCall> = emptyList()` (default keeps all existing constructors working).
- Add an internal pure mapper (unit-testable, no Android deps):
  `internal fun List<AgentPart.Tool>.toUiToolCalls(): List<UiToolCall>` using `toolCallId`, `toolName`, `input`, `isExecuted`, first `Text` part of `output` as result, `isError` = parsed output JSON has `"error"` key. Pretty-print result JSON with `Json { prettyPrint = true }`, fall back to raw text.
- In `runChat()`'s collect block (~line 445, where `assistantMessage.getTools()` is already iterated): map `assistantMessage.getTools().toUiToolCalls()` and include it in the existing `_messages.update { ... it.copy(...) }` for the streaming path. Add it to the final appended `UiMessage` in the non-streaming path (~line 490). Existing busyStatus/image-attachment logic stays untouched.

### 2. `app/src/main/java/com/naira/assistant/presentation/main/pages/ChatPage.kt`

- `MessageBubble`: before the text, render `message.toolCalls` as a `Column` of `ToolCallChip`s (spaced 6.dp, only when non-empty).
- New `ToolCallChip` composable:
  - Collapsed row: tool icon (`Icons.Outlined.Build` tinted `Aqua`) + friendly name (tool name with `_`→space, title-cased) + trailing status — `CircularProgressIndicator` while running, `Icons.Outlined.Check` in success green when done, `Icons.Outlined.Close` in `ErrorText` red when failed + `Icons.Outlined.ExpandMore` rotation.
  - Tap toggles expansion; expanded shows "Arguments" (`tool.input` pretty-printed JSON) and "Result" blocks in `FieldSurface` boxes with `TextSoft`/`TextHigh`, small font. Skip empty sections.
  - Expansion via `rememberSaveable { mutableStateOf(false) }` — LazyColumn items already use `key = { it.id }`, so state survives scroll disposal.
  - New local colors near existing ones (line ~84): `ToolChipSurface = Color(0xFF0B1219)`, `ToolSuccess = Color(0xFF4ADE80)` (same convention as SettingsScreen).
- Auto-scroll: extend the `LaunchedEffect` keys (~line 170) with `latestToolCount = messages.lastOrNull()?.toolCalls?.size ?: 0` so a new tool call scrolls into view like a streamed chunk does.

### 3. New test `app/src/test/java/com/naira/assistant/presentation/main/AssistantToolMappingTest.kt`

Pure JVM JUnit tests for `toUiToolCalls()`: running state (`isExecuted=false` → `isRunning`), success (text output without error → `isError=false`, result extracted), failure (output JSON with `"error"` → `isError=true`), pretty-print fallback on unparseable output. Pattern follows existing `AssistantMoodTest`.

## Verification

1. `./gradlew.bat :app:compileDebugKotlin` — clean compile.
2. `./gradlew.bat :app:testDebugUnitTest` — all tests pass (new mapping tests + existing suite).
3. Manual check (user): send "set a timer for 1 minute" or "what time is it?" → a chip appears with a spinner while running, resolves to a green ✓, and expands to show arguments + result.
